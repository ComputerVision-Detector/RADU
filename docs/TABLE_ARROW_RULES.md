# 표·화살표 규칙 설계 제안

2026-10-21 후속 구현: 테두리 표·직선 화살표의 초기 규칙과 파이프라인 연결을 완료했습니다. 현재 구현 범위는 [구현 기록](STRUCTURE_RULES_IMPLEMENTED.md)을 참고하세요. 아래는 최초 설계안입니다.

현재 src/cv/detector.py는 OpenCV 모폴로지 선 처리와 Hough 선분 및 화살촉 후보 검출을 포함합니다. 후보 검출이 구조 정답을 보장하지는 않습니다. 아래는 후속 구현 제안이며 구현·성능 검증 완료를 의미하지 않습니다.

## 공통

기울기·원근 보정 후 검출하고 결과 좌표는 원본 이미지 좌표로 역변환합니다. 임계값은 고정 픽셀 대신 페이지 크기, 선 굵기, OCR 글자 높이의 비율로 설정합니다. 원본 보존, 텍스트 인식용 이미지, 구조 검출용 이미지를 분리해 선 제거로 글자 획이 사라지는 문제를 피합니다. 파라미터·규칙 버전·판정 근거를 결과에 기록합니다.

## 표

1. 이진화와 가로·세로 모폴로지로 선을 추출하고, 방향·거리·간격이 맞는 끊긴 선을 결합합니다. 기울어진 표는 보정 후 처리합니다.
2. 수평·수직 교차점과 반복 정렬된 구획을 함께 검사합니다. 단일 사각형, 밑줄, 종이 줄무늬를 표로 확정하지 않습니다.
3. 교차점으로 행·열 경계를 만들고, 내부 경계의 부재와 주변 경계의 연속성을 함께 확인해 병합 셀을 추정합니다. 경계가 흐린 경우 곧바로 병합으로 확정하지 않습니다.
4. OCR 텍스트의 셀 포함 면적과 중심을 이용해 셀에 할당합니다. 경계를 넘거나 여러 셀과 비슷하게 겹치면 검수 대상으로 남깁니다.
5. 테두리 없는 표는 텍스트의 반복된 x 정렬·y 간격으로 별도 처리합니다. 문단·목록 오검출을 확인하기 전에는 자동 확정을 제한합니다.
6. table_id, bbox, cell_id, row, col, rowspan, colspan, text_ids를 저장합니다. 텍스트 문자열 평가와 셀 배치 평가는 구분합니다.

## 화살표

1. Hough 선분으로 직선 후보를 만들고 가까우며 방향이 일치하는 선분을 결합합니다. 긴 선 하나만으로 화살표로 판정하지 않습니다.
2. 끝점 주변에 모이는 두 짧은 획 또는 채워진 삼각형의 방향으로 화살촉을 확인합니다. 양 끝에 화살촉이 있으면 양방향입니다. 검출이 불명확하면 방향 미확정으로 남깁니다.
3. 화살촉 반대쪽을 시작점, 화살촉 쪽을 도착점으로 두고, 근처 글상자·도형의 경계까지 거리와 진행 방향 일치도를 함께 계산해 연결합니다. 가장 가까운 중심만 이용하지 않습니다.
4. 두 후보 점수가 비슷하거나 거리가 멀면 연결을 미확정(null)으로 남깁니다. 교차점이 있다는 이유로 두 선을 연결하지 않습니다.
5. 초기 지원은 직선·단방향부터 시작하고, 꺾인 선·양방향·곡선·분기선을 별도 유형으로 늘립니다. 곡선은 직선 Hough만으로 충분하지 않아 skeleton/contour 기반 경로 추적을 별도로 검증합니다.
6. arrow_id, path, head 위치, direction, source_id, target_id, 판정 근거를 저장합니다. 화살표에 붙은 텍스트도 별도 텍스트 객체로 유지합니다.

## 최소 검증

텍스트 전사 라벨만으로 구조의 정확도를 평가할 수 없습니다. 개발용 일부 페이지에 표의 셀 좌표·행열·병합과 화살표의 경로·방향·연결 대상을 별도로 라벨링합니다. 표는 셀 검출 precision/recall 및 행열·병합 일치율, 화살표는 검출 precision/recall과 방향·연결 대상 정확도를 나눠 확인합니다. 미확정 비율도 함께 기록합니다. 충분한 검증 전에는 confidence를 확률로 표현하지 않습니다.
