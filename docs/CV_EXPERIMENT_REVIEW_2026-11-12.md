# RADU CV 실험 재검토 및 유지 결정 — 2026-11-12

CV 범위(전처리·텍스트/도형/화살표 검출·crop·OCR·순서/관계 연결)만 판단한다. Qwen의 페이지 전사 학습·기존 OCR 뒤 언어 교정은 최종 순위에서 제외했다. 새로운 사람 검수를 기다리지 않고 기존 GT를 고정한 연구 비교를 계속할 수 있지만, AI 초안의 검수 상태를 바꾸거나 일반화 성능으로 발표하지 않는다.

## 결정

**현재까지 CV에서 가장 유의미한 실제 정확도 개선은 최초 PaddleOCR-VL 1.6 언어 LoRA의 줄 인식 실험이다.** 언어 decoder adapter를 학습한 모델이지만 과제와 평가는 이미지 crop의 문자 인식이므로 OCR을 포함한 CV 성과로 분류한다. 이것을 검출기 개선이라고 부르지는 않는다.

**검출 단계만 따로 보면 CTC 사전 필터가 정상 영역을 버리던 문제를 찾아 raw500개를 복원한 실험이 가장 중요하다.** 새로운 detector를 학습해 얻은 성과가 아니라, detector 이후의 잘못된 범위 제한을 찾아낸 결과다.

유지 조합은 기존 detector + 최초 VL 언어 LoRA + 기존 crop이다. 새 연구 비교의 batch 규약은 singleton-v1로 고정하고 과거 batch4 점수는 별도 보존한다. VL에서 CTC 사전으로 정상 텍스트를 제거하지 않으며, 수식/기호와 일반 텍스트의 범위는 downstream에서 명시적으로 다룬다. 이 문서는 유지/후속 투자 판단이며 운영 적용·새 학습·추론 변경을 실행한 기록이 아니다.

## 확인 범위와 증거

- GitHub connector로 실제 원격 branch 목록9개를 끝까지 확인했다. 각 branch의 로컬 Git tree도 열거했다. 원격 최신 branch의 모든 파일 내용을 줄 단위로 검토했다고 주장하지 않는다.
- 주 작업본, HybridOCR 보관본, radu-v2-production의 CV24모듈을 해시로 대조했다. 동일 내용은10종이고 기존7종 CV 모듈은 세 작업본에서 전부 같다. 보관본 복제를 독립 실험으로 중복 집계하지 않았다.
- 두 배포 tar.gz의 전체 member 목록과 보고서/manifest 항목을 안전하게 읽었다. 배포 site 디렉터리와65개 보고서 경로를 인덱싱했다. 주된 CV 실험 보고서와 관련 실제 코드/예측/선택 기록을 집중 검토했다. binary 가중치를 소스처럼 해석하거나 비CV 전체 코드를 수동 완독했다고 주장하지 않는다.
- 최신 OCR 종합 기록, 최초 VL/CTC 학습, round2/clean-vision, FP201 감사, raw500 복원, crop 경계, batch 진단, 기존 OpenCV 구조 규칙/관계 연결, 과거 자동 layout/tiling 실험의 CV 부분을 대조했다.
- 새 GPU 추론이나 새 학습 없이 저장된 예측으로6개 조건의 CER을 독립 Python 동적 계획법으로 재계산했다. NFC·공백 병합은 별도 구현했고 ID·표본·정답 문자 분모의 일치를 검사했다.

전체 경로/해시·중복 묶음·branch 목록은 `data/experiments/cv_archive_review_20261112/inventory.json`, 재계산 값은 `independent-CER-rechecks.json`, 입력 hash는 `evidence-lock.json`이다.

## 실제 채택 가치가 가장 큰 실험: 최초 VL 언어 LoRA

동일17페이지/16그룹/235 GT crop/4,401문자에서:

| 지표 | 공식 VL | 최초 언어 LoRA |
|---|---:|---:|
| micro CER |21.6087%|15.2238%|
| 공백 제외 CER |22.1532%|15.5129%|
| 오류 수 |951|670|
| S/D/I |585/190/176|447/102/121|
| 완전 일치율 |14.4681%|19.5745%|

절대6.3849%p, 상대29.5478% 오류 감소다. 공백 제외와 S/D/I도 같은 방향으로 개선되어 공백만 맞춘 효과가 아니다. 재계산한 수치는 원래 기록과 일치했다. 기존 page bootstrap95% 개선 구간은4.2956~9.0026%p다. 이미 관찰한 작은 진단 집합이므로 미사용 독립 필자 일반화의 근거는 아니다.

선택 adapter는 `data/experiments/ocr_v2_vl_lora/train/best-adapter/adapter_model.safetensors`, SHA256 `ab1bfcfba5c0711ebfc82e83432eca13b47fbb48ca0800d9e7b4d590e15421e5`로 현재 일치한다.

round2의 추가 학습/해상도 증가/가중합과 round3의 train 정제 후 언어/시각 adapter는 부모를 대체할 CER 근거가 없다. 같은 validation244에서 부모12.7917%, 추가 학습12.8095%, 고해상도 학습13.3262%, 가중합12.9521%, 정제 언어12.7917%, 정제 시각12.8630%였다. 다른 batch 구성이었던12.9877%를 이 표에 섞지 않았다. 따라서 학습 라운드를 더 돌리는 것이 현재 최우선이라는 증거는 없다.

## 검출 진단의 핵심: CTC 범위 필터 복원

원래 detector raw500개에서 CTC 평가 규칙 때문에103개가 빠져397개만 남아 있었다. 이전397개의 ID/bbox/crop/인식문을 보존하고103개를 복원했다. CTC가 정상 GT32개를 제외한 원인은 연결선/불릿/일부 문자였고, 복원 예측이 그중28개와 IoU0.5로 매칭됐다.

같은 GT v2/17페이지/306GT/5,695문자에서:

| 지표 |397 bank|500 bank|
|---|---:|---:|
| TP/FP/FN |271/33/35|299/47/7|
| Recall |88.5621%|97.7124%|
| F1 |88.8525%|91.7178%|
| 페이지 CER |30.0615%|28.9025%|
| S/D/I |540/542/630|528/147/971|

누락을 크게 줄였지만 삽입이 늘었다. 페이지 CER 개선의 bootstrap 구간은0을 포함한다. detector-assisted GT라 독립 detector benchmark도 아니다. 따라서 이 발견의 가치는 잘못된 필터 계약 수정이며, 검출기 학습 성능의 향상을 입증한 것은 아니다.

FP201 감사도 GT 누락94/제외82/분할·병합11/비텍스트1/보류13/확정 전체 중복0이라는 AI 잠정 판단이었다. FP201을 모두 detector의 실제 오탐으로 보고 강한 NMS나 새 detector 학습을 우선할 근거는 약하다.

## crop과 순서: 개선 대상은 맞지만 채택된 성공 방법은 없음

동일 명확 대응 M138영역/16페이지/2,501문자에서 GT crop C0는347오류/CER13.8745%, 검출 crop C1은383오류/CER15.3139%였다. 이번 독립 재계산에서도 일치했다. 매칭 가능한 영역의 경계/resize 변경 영향이며 누락까지 포함한 전체 detector 효과가 아니다. 따라서 crop·분할/병합 품질은 다음에 검증할 CV 대상이다.

다만 현재 밝기 trim 방법은 탈락이다. 같은 validation244/5,613문자에서729→769오류, CER12.9877→13.7003%로 악화했고 어두운 배경에서 문장 앞부분이 실제 잘렸다. 밝기·원근·회전 보정 구현이 존재한다는 사실만으로 OCR 향상을 주장하지 않는다.

동일 인식문138영역의 순서만 바꾼 결과는 CER14.3729→14.2204%,813쌍 중 역전1→0,4편집 오류 차이였다. 전체 페이지 순서 문제가 작다는 뜻은 아니다. 흐름도/미대응 영역의 의미 순서는 별도 미확정이다.

GT v1~v4/ignore/geometry 변경에 따른84.7647→30.0615 또는25.0084→23.6041%는 모델이 좋아진 결과가 아니므로 성공 모델 순위에서 제외했다.

## 중요한 재현성 발견: batch 구성 차이

기록된 변경13영역+CONV2+대조1영역에서 구성만 바꿔13개 출력 차이를 재현했다. 같은 대상의 pixels/processor tensor/token은 같았다. 한 사례에서는 첫 vision layer의 MLP 입력이 같아도 BF16 fc1 출력부터 달랐다. 정확한 CUDA kernel 원인은 확정하지 않았다.

동일 batch와 singleton 반복은 각각15쌍 모두 input tensor/token/score receipt까지 일치했다. 이후 CV 모델 비교는 기존 crop을 batch1로 실행하는 `RADU-research-singleton-v1`을 사용한다. 이는 최고 CER을 골라 정한 규약이 아니다. 과거 batch4 결과와 직접 개선량을 만들지 않는다. CONV2는 고정 언어 LoRA의 모든 조건에서 conv2였으므로 그 사례가 재현됐다고 과장하지 않는다.

## 도형·표·화살표와 전처리의 현재 수준

`detector.py`의 OpenCV 경로와 `structure_rules.py`는 후보 생성이다. 코드상 trained YOLO 경로가 있어도 실제 가중치·실문서 비교 지표가 확인되지 않은 기능을 학습 검출기 성과로 세지 않았다. 규칙 기반 테두리 표/병합 셀·직선 화살촉·방향/끝점 연결은 합성 검사와 실행 증거는 있다.

그러나 실제5장에서는 화살표 후보가1페이지7개/나머지0개, 표0개였다. 이는 정답 수/정확도가 아니고 제본·노트 선 오검출과 작은 화살표 누락도 관찰됐다. precision/recall과 비교 개선량이 없어 가장 성공한 CV 실험으로 고르지 않는다. 곡선/꺾인 화살표·테두리 없는 표·촬영 원근에 대한 정확도는 입증되지 않았다.

`preprocess.py`의 사각형 원근·Hough 회전·CLAHE 밝기 보정도 구현돼 있지만 OCR 동일 조건 ablation을 찾지 못했다. 전처리를 일괄 추가하는 선택을 지지할 자료는 없다. 과거 layout/3-tile 분할 역시 그때의 모델/조립 조건에서 validation이 악화했으므로 현재 객체 검출 전략의 성공 증거로 재사용하지 않는다.

## 검수 없이 진행할 때의 CV 우선순위

1. **기준 유지:** 최초 VL 언어 LoRA와 기존 crop. 기존 GT/ignore/진단 split을 버전 그대로 고정하고 미검수 상태를 유지한다. 사람 검수 대기를 필수 중단 조건으로 두지 않는다.
2. **실행 규약 통일:** 다음 비교는 같은 crop/같은 정답/같은 batch1에서 공식 VL과 선택 LoRA를 비교해 새 기준선을 남긴다. 예전 수치와 batch 혼입을 먼저 제거한다.
3. **검출 후 영역 처리:** raw 검출은 보존하고 CTC 사전으로 정상 줄을 버리지 않는다. 본문·수식·기호가 섞이는 영역과 분할/병합·이웃 줄 유입을 구분하는 CV 처리를 validation에서 비교한다. 좋은 점수를 만드는 ignore 임계값 탐색이나 test 맞춤 규칙은 하지 않는다.
4. **검출기 재학습/강한 중복 제거는 후순위:** 현재 자료는 실제 비텍스트/전체 중복이 주원인이라고 입증하지 못한다. 기존 detector가 완벽하다는 뜻은 아니며 구조 화살표의 검증 부족과 텍스트 detector의 오류를 혼동하지 않는다.
5. **일괄 밝기 trim/추가 LoRA는 채택하지 않음:** 확인된 정보 손실과 반복 학습의 정체를 고려하면 당장 우선 투자할 근거가 약하다.

이번 검토에서는 새 모델/optimizer/추론을 실행하지 않았고, 기존 예측·GT·체크포인트·운영 경로는 변경하지 않았다. 독립 재계산6조건의 ID/분모/오류수 검사가 모두 통과했다. pipeline 코드 변경이 없어 기존79개 회귀를 불필요하게 다시 돌리지는 않았다.
